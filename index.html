阶段项目 · pj-01

60 帧小场景 + 帧预算报告

交付物一个可打包的小场景（固定机位）+ 一份帧预算报告：Game / Render / GPU 时间、最慢线程、1% low、瓶颈归因与三条候选优化。

验收点
  • 报告能复现：写明构建类型、分辨率、画质档位、场景版本与采集时长。
  • 能指出一个瓶颈，并给出改前/改后的对照数字，而不是只写「优化了」。
  • 至少一条候选优化被验证有效，另一条被证伪并说明原因。
常见失败方式
  • 只在编辑器 PIE 里测，不打包，数值与目标平台不可比。
  • 只报平均 FPS，不报长帧与 1% low，尖峰被平均掩盖。
  • 没有固定机位与场景版本，前后数据不可复现。

阶段项目 · pj-02

带流式加载的小地图

交付物一张可高速穿行的小地图（World Partition 或 Level Streaming）+ 流送曲线：常驻单元、内存、IO 随位置变化。

验收点
  • 以冲刺/调试相机速度穿越整图，记录最长帧，证明没有长时间卡顿。
  • 给出半径/单元大小与常驻内存的关系，并说明选择依据。
  • 冷启动与热缓存两种条件都测过，不只测编辑器。
常见失败方式
  • 只按正常走路速度测，触发不了流送压力。
  • 不断加大半径掩盖问题，内存与加载时间一起失控。
  • 只看画面有没有空洞，不看流送统计与内存曲线。

阶段项目 · pj-03

渲染特性取舍台

交付物同一场景的 Lumen / 烘焙（或移动端 Forward / Deferred）A/B 配置 + PSO 预缓存记录 + 一页取舍说明。

验收点
  • 给出两条路径的通道级 GPU 时间与画质对比，机位与分辨率固定。
  • 在薄墙、屏幕外、快速移动光源三种边界下记录漏光/延迟表现。
  • 打包构建中 PSO 未命中次数显著下降，并附收集覆盖率。
常见失败方式
  • 只开关特性，不看同一基线，结论无法归因。
  • 只在理想场景测，不测薄墙与屏幕外，漏光被掩盖。
  • 只在编辑器里预热 PSO，打包后仍然卡。

阶段项目 · pj-04

带预测回滚的联机 demo

交付物listen server + 2 客户端的移动与一个可预测技能 demo + 延迟/抖动测试记录 + 技能预测清单。

验收点
  • 在 100/200ms 延迟与抖动下记录预测偏差、回滚次数与观感。
  • 构造一次服务器拒绝（冷却/距离/权威判定），客户端正确回滚且表现被纠正。
  • 给出哪些技能预测、哪些不预测的理由，并说明回滚窗口的选择。
常见失败方式
  • 只在 LAN 测，延迟与抖动没有真正被验证。
  • 把所有技能都开预测，回滚成本与表现错位失控。
  • 只同步状态不同步表现（Cue），回滚后画面与数值对不上。

阶段项目 · pj-05

规模化与工程化演练

交付物200 单位群体场景 + 虚拟化 UI 长列表 + CI 性能门禁 + 发布/回滚 runbook。

验收点
  • 给出群体 AI 的 CPU 曲线与分档阈值，证明上限可解释。
  • 长列表滚动时 UI 每帧成本与总条目数解耦，并有数据。
  • CI 拦住一次人为性能回归；按 runbook 完成一次灰度发布与回滚演练。
常见失败方式
  • 只优化单个 AI，不看规模与寻路请求集中。
  • UI 只做视觉虚拟化，数据仍全量绑定，滚动照样卡。
  • 门禁阈值拍脑袋，误报后直接关掉，回归再次漏过。

前置依赖：谁必须先学，谁能并行

箭头表示「必须先学」。同阶段的上下箭头表示阶段内先后；跨列箭头表示跨阶段前置。切换方向会高亮相关节点，其余降权。

左 → 右：阶段推进 实线箭头：硬前置 同一阶段内的并行组见右侧说明

跳过会踩什么坑

渲染管线基础→性能分析与预算必须先学

跳过：后面所有「卡」只能靠感觉，无法判断是 CPU 还是 GPU。

性能分析与预算→全局光照与 Lumen必须先学

跳过：会把 Lumen 成本当成「画质税」，不知道贵在哪个通道。

资源加载与卡顿→World Partition 流送必须先学

跳过：会把流送卡顿误判为半径问题，越调越糟。

World Partition 流送→资源管线与分包必须先学

跳过：分包边界与流送单元脱节，补丁体积和换页压力同时失控。

网络同步与预测回滚→GAS 与技能预测必须先学

跳过：会把「预测」当成万能开关，不知道哪些技能根本不能预测。

网络同步与预测回滚→反作弊与信息裁剪必须先学

跳过：会把信息裁剪和延迟补偿混为一谈，做出既卡又漏的防护。

网络同步与预测回滚→特殊移动与预测必须先学

跳过：特殊移动的回拉会被当成动画或状态机 bug。

动画与 Motion Matching→特殊移动与预测必须先学

跳过：会把移动抖动归因到动画，改错地方。

物理、破坏与载具→特殊移动与预测必须先学

跳过：特殊移动的碰撞/容差问题会被当成状态逻辑错误。

性能分析与预算→自动化、构建与线上运维必须先学

跳过：CI 门禁没有可信基线，只能拦构建失败，拦不住性能退化。

资源管线与分包→自动化、构建与线上运维必须先学

跳过：门禁只盯帧率，包体与补丁体积继续劣化。

群体 AI 与导航→UMG / Slate 性能可并行

可并行：两者都只依赖 perf；先做哪个取决于项目是「单位多」还是「界面重」。

哪些可以并行

阶段 1 可并行性能分析与预算 / GC 与内存

两者都只依赖 render-basics，可并行；先学哪个取决于当前痛点是帧还是 GC。

阶段 2 可并行资源加载与卡顿 / World Partition 流送

loading 是 streaming 的前置，不建议并行；asset 需要两者都读过之后再动。

阶段 3 可并行全局光照与 Lumen / 移动端渲染与带宽 / 着色器编译与 PSO

三者都只依赖 render-basics + perf，可并行；但都建议先完成阶段 1 的基线报告。

阶段 4 可并行GAS 与技能预测 / 反作弊与信息裁剪 / 物理、破坏与载具 / 动画与 Motion Matching

都依赖 net；gas/anticheat/physics/animation 可在 net 之后并行，movement 需要 animation + physics + net 三者。

阶段 5 可并行群体 AI 与导航 / UMG / Slate 性能

可并行；engineering 需要 perf + asset，建议放在最后。
