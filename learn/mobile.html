移动端渲染：带宽比算力更容易先撞墙

移动 GPU 和桌面不是「缩小版」：它把屏幕切成小块，在片上内存里完成着色，最怕的是把数据搬来搬去。理解这一点，就能解释为什么降分辨率有用、为什么半透明贵、为什么读回屏幕代价巨大。

01

你会遇到什么问题

画面不复杂，手机却发烫掉帧

场景里没几个模型，光源也不多，但手机跑十分钟就烫、帧率下滑。你把材质精度降低、关掉一些特效，收益有限；换到另一台 GPU 不同的手机上，同样的内容表现又不一样。

常见症状：
  • 帧率被 GPU 限制，但看不出明显的着色复杂度
  • 半透明粒子、后处理、全屏特效一加就掉
  • 设备发热降频后性能持续下滑，短时测试看不出来
  • 不同 GPU 厂商的机型表现差异大，难以统一调优
02

一句话直觉

桌面 GPU 像一个大车间，原料可以随时从仓库取；移动 GPU 像一条只有很小工作台的流水线，东西拿进拿出都要花时间。

Tile-Based Deferred Rendering，移动 GPU 常见的分块延迟渲染架构。">TBDR（Tile-Based Deferred Rendering）把屏幕分成 tile，先在片上内存完成不透明物体的深度与着色，最后才把结果写回主存。片上内存很小但极快，主存大但访问昂贵。因此「多画一层半透明」「读写一张全屏 RT」在移动端都会被放大成带宽成本，而不是简单的算力问题。

类比的边界：工作台类比不体现「厂商实现差异」：不同 GPU 的 tile 大小、压缩格式与调度策略不同，同一份内容的表现会有差异，必须按机型档位实测。

03

原理图解

TBDR 先把几何按 tile 分桶，做完整的深度测试（Hidden Surface Removal），尽量只对最终可见的像素着色。

不透明物体的着色在片上内存完成，避免每个像素都往返主存；这也是「先深度后着色」能省带宽的原因。

半透明无法靠深度剔除，必须按层混合；层数越多，重复着色与读写次数越多，overdraw 直接变成带宽。

任何需要「读回上一张全屏结果」的操作（后处理、某些效果、屏幕空间效果）都可能触发 tile 的存取，成本远高于纯片上操作。

移动端常用带宽优化手段是压缩纹理、降低 RT 精度、减少全屏 pass 与半透明层数；分辨率下降能同时减少像素数与带宽，所以通常最有效。

展开：再深一层的机制与边界
为什么「关掉一个特效」有时收益很小：如果该特效本来就在片上完成且层数很低，它的算力成本可能不大；真正贵的是额外的全屏 RT 与读写。定位时要看带宽与 pass 数，而不是只看「特效看起来复不复杂」。
04

关键代价

带宽
RT 读写、半透明混合与全屏 pass 是主要来源。
填充率
overdraw 直接乘上像素数，移动端尤其敏感。
发热 / 降频
持续高负载会触发降频，短时测试无法反映。
画质
降分辨率、降 RT 精度是最直接的带宽手段，但会牺牲清晰度。
机型适配
不同 GPU 的 tile 与压缩策略不同，需要分档与实测。

条形为相对量级（1–5 档），不对应具体毫秒、兆字节或人力数字。判断取舍时看「哪一项不可接受」，而不是追求每项都低。

06

常见误区

误区 1用桌面机的表现推断移动端，只按比例降分辨率。
正确理解移动端瓶颈常是带宽与发热，不是算力。必须在目标机型上实测，并观察降频后的持续表现。
误区 2认为半透明「只是多画一层」，成本可以忽略。
正确理解半透明无法被深度剔除，每层都要重复着色与混合，层数叠加会直接推高填充与带宽；移动端应严格限制层数。
误区 3短时间跑 60fps 就认为性能达标。
正确理解发热降频会让性能在几分钟后下滑。要做持续负载测试（10–30 分钟），记录帧率与温度/降频状态。
07

动手复现

前提：UE 5.x；用 Mobile Preview 或真机（Android/iOS），Feature Level 设为 ES3.1/ES3.2；overdraw 需 GPU 抓帧。

01在目标机型上叠加几层半透明粒子，记录帧时间与 GPU 统计。
预期现象：GPU 时间随层数明显上升，验证 overdraw 是主要成本。
02把渲染分辨率从 100% 降到 70%，重复同一场景。
预期现象：帧时间下降明显，说明带宽/填充是瓶颈之一。
03关闭一个全屏后处理 pass，对比帧时间。
预期现象：减少一次全屏读写，收益可能比关掉一个复杂材质更大。
04把 RT 精度与纹理压缩格式调整一档，观察画质与带宽变化。
预期现象：得到可量化的取舍，而不是凭感觉选画质。
05持续运行 15 分钟并记录帧率曲线。
预期现象：看到降频后的下滑，确认短时测试不足以判断。

步骤在编辑器内 5 步以内可复现；预期现象用来自检机制是否成立，不要求截图一致。

08

自测

1. 为什么移动端「降分辨率」通常最有效？
解析：因为分辨率同时减少像素数、填充率与 RT 读写带宽，而移动端最容易被带宽限制；它不需要改内容就能立刻降低多个成本项。
方案：动态分辨率与设备分级问题：中低端机帧率不稳并伴随发热降频
2. TBDR 中半透明为什么特别贵？
解析：因为半透明不能靠深度测试剔除，必须按层混合；每一层都要重复着色并读写，overdraw 直接转成带宽与填充成本。
方案：TBDR、带宽与填充率：过度绘制治理问题：移动端 GI/阴影方案照搬桌面导致不可用
3. 为什么移动端必须做持续负载测试？
解析：持续高负载会触发热降频，短时跑满帧并不代表稳定。只有记录十几分钟以上的帧率曲线，才能看到真实体验。
