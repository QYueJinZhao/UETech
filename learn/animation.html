动画系统：为什么人一多就掉帧

动画的成本不在「播一段」，而在「每帧为每个角色算出一份骨骼姿势」。这一章讲姿势来源、更新频率与 LOD，解释为什么同屏角色数是最直接的开关。

01

你会遇到什么问题

同屏二十个敌人，帧率掉一半

单人对战很流畅，一到群战或大规模 PvE 就掉帧。你把动画蓝图简化了一点，收益有限；降低骨骼数量有效但角色明显变僵硬。策划还要求加入更自然的转身与起步。

常见症状：
  • 同屏角色数上升时帧率下降，且与模型面数不成比例
  • 动画蓝图节点越多，CPU 越高
  • Motion Matching 上线后动画质量提升，但开销明显
  • 远处角色仍在跑全量动画，浪费在看不见的地方
02

一句话直觉

动画像每帧给每个角色「重新算一遍姿势」：看的角色越多、每帧算的次数越多，CPU 就一直被占着。

骨骼动画的运行时成本主要是姿势求值（动画蓝图、混合、IK、物理动画）与蒙皮。">骨骼变换更新。它与角色数量、骨骼数和蓝图复杂度近似线性相关；网格面数影响的是蒙皮/渲染，不是动画求值。Motion Matching 每帧要在姿势库里检索最匹配的片段，质量更好但检索成本更高。所以控成本的第一开关是「同屏数量 + 更新频率 + LOD」。

类比的边界：算姿势类比不体现「并行与缓存」：部分求值可并行、部分结果可缓存，但骨骼更新与蒙皮仍要落到实际硬件上，收益取决于实现。

03

原理图解

每帧每个可见角色都要做姿势求值：状态机/混合/IK/物理动画，然后更新骨骼变换，最后交给蒙皮。

动画求值成本与角色数近似线性，也与骨骼数、蓝图复杂度相关；网格面数主要压在蒙皮与渲染。同屏人数与更新频率是最有效的预算杠杆。

更新频率可降级：远处角色可降低求值频率或用插值保持观感，节省大量 CPU。

Animation LOD 是常用手段：远处降骨骼数、简化蓝图、关闭 IK 与物理动画，甚至改用烘焙或顶点动画。

Motion Matching 用姿势库检索替代手工状态机，质量与自然度更高，但每帧检索与内存占用都更大，需要按角色重要度分档。

04

关键代价

CPU
姿势求值、蓝图与 IK 是主要开销，随角色数线性增长。
内存
姿势库与动画数据常驻，Motion Matching 更明显。
美术规范
骨骼数、蓝图复杂度与动画数量直接决定成本。
画质 / 手感
降频与 LOD 会牺牲细节，需要按距离与重要度分档。
团队协作
动画预算需要与策划的同屏人数目标对齐。

条形为相对量级（1–5 档），不对应具体毫秒、兆字节或人力数字。判断取舍时看「哪一项不可接受」，而不是追求每项都低。

06

常见误区

误区 1以为降低模型面数就能解决动画开销。
正确理解动画求值成本主要来自姿势求值与骨骼更新，与面数关系小；但蒙皮仍随顶点数增长，别把两者混为一谈。先看同屏角色数与更新频率。
误区 2所有角色都用同一套全量动画。
正确理解远处角色看不见细节，应做 Animation LOD 与降频；否则预算被浪费在玩家注意不到的地方。
误区 3Motion Matching 上线后不做分档，所有单位都用。
正确理解它质量高但成本也高。应只给主角与关键角色使用，群演回退到状态机或简化路径。
07

动手复现

前提：UE 5.x；Motion Matching 需启用 Animation 相关插件并准备姿势库/轨迹数据；用 stat anim 与 Insights 对照。

01在场景里逐步增加到 20 个带动画的角色，记录 stat game 与动画相关统计。
预期现象：CPU 随角色数近似线性上升，面数变化对动画求值影响不明显（蒙皮成本另算）。
02对远处角色开启 Animation LOD 或降低更新频率。
预期现象：CPU 明显下降，近处观感基本不变。
03把一个角色切换到 Motion Matching，对比同屏 20 人的开销。
预期现象：质量提升但成本上升，验证「按重要度分档」的必要性。
04关闭远处角色的 IK 与物理动画。
预期现象：进一步降低开销，确认这些子系统是可见的成本项。
05用 Insights 查看动画线程的占用与热点。
预期现象：能指出是姿势求值、蓝图还是骨骼更新占大头。

步骤在编辑器内 5 步以内可复现；预期现象用来自检机制是否成立，不要求截图一致。

自测

1. 为什么动画成本和模型面数关系不大？
解析：因为动画求值主要是每帧的姿势求值、混合与骨骼变换更新，与骨骼数、蓝图复杂度和角色数量相关；面数影响的是蒙皮与渲染，不是动画求值。
方案：大量敌人动画预算：动画 LOD/更新频率/实例化问题：动画状态机爆炸与过渡抖动
2. Animation LOD 的核心思路是什么？
解析：按距离/重要度降低动画更新频率、骨骼数与功能（IK、物理动画），把预算集中在玩家看得近、看得多的角色上。
问题：Motion Matching 数据库过大导致匹配抖动/成本上升方案：大量敌人动画预算：动画 LOD/更新频率/实例化
3. Motion Matching 的主要代价是什么？
解析：每帧要在姿势库里检索匹配片段，CPU 与内存成本都更高；同时调试更抽象，需要采集与维护较大的动画数据。
