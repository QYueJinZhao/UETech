反作弊：客户端知道得越少，作弊空间越小

反作弊不是「检测外挂」这一件事，而是从一开始就不把不该给客户端的消息发过去。这一章讲服务器权威与视野裁剪，理解为什么「本地看得见」不等于「应该下发」。

01

你会遇到什么问题

透视外挂能看到墙后的敌人

玩家反馈有透视/雷达作弊：能看到视野外、墙后的敌人位置。你查看代码发现服务器把整张地图的玩家位置都复制给了每个客户端，只是客户端「不显示」。

常见症状：
  • 客户端能读到不该知道的信息（位置、血量、掉落）
  • 关键判定在客户端做，改内存就能改结果
  • 作弊检测只能事后封号，无法阻止即时优势
  • 正常玩家因延迟补偿感到「被打了没反应」
02

一句话直觉

反作弊像发考试卷：不该让人看到的答案，最好的保护是根本不印在纸上，而不是印了再要求别翻页。

只要数据到了客户端，理论上就能被读出来。所以第一道防线是「不发」——服务器按视野与相关性裁剪，只下发玩家需要的信息。第二道防线才是「不敢改」——关键判定放在服务器，客户端只提交输入。检测与封禁是第三道。

类比的边界：考卷类比不体现「延迟补偿」：为了手感，服务器需要在历史上回溯判定；这给了攻击者「制造延迟」的空间，所以判定逻辑本身就是攻防焦点。

03

原理图解

服务器按视野、距离与游戏规则计算「谁能看到谁」，只向相关客户端复制该单位的信息，这叫相关性裁剪。

信息裁剪不等于渲染裁剪：前者决定「数据到不到客户端」，后者决定「画不画出来」；只做后者等于把答案发给所有人。

关键判定（命中、拾取、伤害、掉落）应在服务器执行；客户端提交输入与意向，不能提交结果。

延迟补偿在服务器端回溯历史位置，属于「为了手感接受的风险」，需要配合校验与阈值，防止被滥用。

检测类手段（完整性校验、行为分析）是兜底，不是第一道防线；它们通常滞后，只能降低长期收益，不能阻止即时作弊。

04

关键代价

服务器 CPU
视野计算、相关性判定与回溯校验都要服务器算。
带宽
裁剪越精细，消息越少；但计算与同步逻辑更复杂。
手感
服务器权威越彻底，客户端反馈越需要预测来补救。
实现复杂度
相关性规则、回溯窗口与校验阈值都要长期调。
误判风险
过度裁剪会导致正常玩家看到「信息缺失」（如队友消失）。

条形为相对量级（1–5 档），不对应具体毫秒、兆字节或人力数字。判断取舍时看「哪一项不可接受」，而不是追求每项都低。

06

常见误区

误区 1只在客户端隐藏信息，就认为防住了透视。
正确理解数据一旦下发就能被读取。必须在服务器做相关性裁剪，让不该知道的信息根本不到客户端。
误区 2把命中判定放在客户端，图省服务器算力。
正确理解客户端判定等于把结果交给攻击者。应客户端提交输入、服务器判定，再用预测与表现弥补手感。
误区 3依赖检测封号作为唯一手段。
正确理解检测通常滞后且可能误伤。它应与裁剪、服务器权威叠加使用；否则作弊者仍能在被发现前获得大量优势。
07

动手复现

前提：UE 5.x；用专用服务器或 listen server 多客户端；信息裁剪必须在服务器侧验证，客户端只做表现。

01在联机调试中查看某个客户端收到的 Actor 列表（或复制可视化）。
预期现象：能看到视野外的单位是否也在列表中，验证是否真的做了裁剪。
02站到墙后观察敌方单位是否仍被复制到本地。
预期现象：若仍收到位置，说明只做了渲染隐藏，没有做信息裁剪。
03把一次命中判定从客户端改到服务器，观察延迟下的表现。
预期现象：命中结果变权威，但反馈变慢，需要预测/表现层补足。
04人为模拟高延迟，测试延迟补偿的判定窗口。
预期现象：能观察到「回溯」带来的命中差异，以及窗口过大时的风险。
05用一次异常输入（如伪造坐标）验证服务器是否拒绝。
预期现象：服务器拒绝或纠正，确认客户端提交的不是「结果」。

步骤在编辑器内 5 步以内可复现；预期现象用来自检机制是否成立，不要求截图一致。

08

自测

1. 为什么「客户端隐藏」不能防透视？
解析：因为数据已经下发到客户端，攻击者可以直接读取内存或抓包。只有服务器不下发不该给的信息，才真正消除透视的收益。
方案：反透视/雷达：服务器视野裁剪与信息最小化问题：客户端信任导致瞬移/加速/无敌作弊
2. 服务器权威会带来什么代价？怎么弥补？
解析：代价是反馈延迟与服务器算力。弥补方式是客户端预测 + 表现层先行 + 服务器确认后纠正，而不是把判定放回客户端。
问题：服务器判定与客户端表现不一致导致误判方案：命中验证与 Lag Compensation / Server Rewind
3. 延迟补偿为什么是攻防焦点？
解析：它需要服务器回溯历史位置来判定命中，窗口越大越容易被利用（例如故意制造延迟）。所以窗口与校验阈值必须谨慎设定。
方案：命中验证与 Lag Compensation / Server Rewind面试题：如何建立可审计的 FPS 反作弊证据链？
